# DuckDB 1.5.4 and C extension ABI upgrade implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Upgrade Razobill's DuckDB loadable C extension, C_STRUCT ABI headers, build system stamping, test harness, CI workflows, and documentation from DuckDB 1.2.x baseline to the latest stable DuckDB v1.5.4 release, while strictly preserving exact lossless invertibility and zero heap allocations on the query hot path.

**Architecture:** Update `thirdparty/duckdbcapi/` amalgamated headers (`duckdb.h`, `duckdb_extension.h`) from official DuckDB v1.5.4 sources. Update extension metadata stamping in `CMakeLists.txt` and `Makefile` (`-dv v1.5.4`, `TARGET_DUCKDB_VERSION=v1.5.4`). Verify that `ext/duckdb/DuckdbExtension.cpp` compiles cleanly with `-Wall -Wextra -Wpedantic -Wconversion` and preserves the 4 registered scalar SQL functions (`RzSplit`, `RzJoin`, `RzTemplate`, `RzHash`). Validate all 14 DuckDB integration test cases and 134,910 assertions against DuckDB 1.5.4 runtime via ADBC, and update Diataxis documentation and CI matrix workflows.

**Tech Stack:** C++20, DuckDB v1.5.4 (C Extension API, `C_STRUCT` ABI, ADBC), CMake 3.20+, Ninja, Doctest, Python 3.9–3.13.

**Spec:** [DuckDB C Extension API Documentation](https://duckdb.org/docs/api/c/extensions) and [DuckDB v1.5.4 Release](https://github.com/duckdb/duckdb/releases/tag/v1.5.4)

## Global Constraints

- **Exact Lossless Invertibility:** `join(split(x)) == x` must hold byte-for-byte across all inputs in DuckDB SQL.
- **Zero Heap Allocation on Hot Path:** Thread-local scratch buffers in `DuckdbExtension.cpp` must eliminate dynamic heap allocations during vectorized vector processing.
- **Public ABI Stability:** Preserve universal C ABI (`RazobillC.h`) and DuckDB function signatures (`RzSplit`, `RzJoin`, `RzTemplate`, `RzHash`).
- **Surface Budget Limit:** Enforce strict budget of <= 4 registered SQL functions, 0 legacy aliases, and 0 banned terms via `tools/CheckSurfaceDuckdb.py`.
- **Thirdparty Exception:** Direct update of `thirdparty/duckdbcapi/` is explicitly authorized by user request for this DuckDB upgrade.
- **Documentation Linters:** Must report 0 errors in `markdownlint-cli2`, `LintDocs.py`, and `VerifyMarkdownLinks.py`.

## Review Focus

- **Metadata Footer Stamping:** `tools/AppendExtensionMetadata.py` must encode `v1.5.4` in FIELD3 with `abi_type: C_STRUCT` (FIELD5) and signature header `4` (FIELD1).
- **Multi-Width List Decoding:** Stride-aware list decoding for `BIGINT`, `INTEGER`, `SMALLINT`, `TINYINT`, `UBIGINT`, `UINTEGER`, `USMALLINT`, `UTINYINT` in `RzJoin` must remain functional without out-of-bounds reads.
- **ADBC Dynamic Loader:** `tests/Support.hpp` must locate and initialize `duckdb.dll` / `libduckdb.so` / `_duckdb.pyd` from DuckDB 1.5.4 without symbol mismatch.
- **Dual Entrypoint Compatibility:** Both `LOAD razobill;` (`razobill_init_c_api`) and `LOAD librazobill;` (`librazobill_init_c_api`) must resolve successfully.
- **Community Metadata Alignment:** `ext/duckdb/description.yml` and `Makefile` must match DuckDB community extension repository standards for v1.5.x.
