Logs are born structured. Razobill keeps them that way.

Your code already knows which part of a log line is fixed and which part is a value. Razobill takes the line apart along that seam, stores the values as plain columns, and gives you the original text back, byte for byte.

Razobill is an open-source log parser. It splits each line into a template and typed values, and rebuilds the exact line from them. C++20 core, with a Python package, a DuckDB extension and a C API. Version 1.1.3, Apache 2.0.

Why not just guess the template?

Most log tools treat parsing as a guessing game. They cluster similar lines, replace the parts that change with a wildcard, and throw the real values away. You then pay to store the raw text anyway.

Razobill reads the line once with a deterministic scanner. The same line always gives the same template, whatever order lines arrive in, and nothing is thrown away.

The math behind it

Razobill is built on Latitude and Doubt by Moustafa Mahmoud Atta (2026). It shows that when a line has only one possible shape, expression splits exactly into content plus latitude, with zero doubt. In plain terms: shape plus values equals the line.

The engine checks that bookkeeping while it runs. Hot paths use AVX-512, AVX2 or NEON, a bump arena, and a 64-bit xxHash of the template.

Try it in a minute

pip install pyrazobill

import pyrazobill as rz

raw = "Accepted publickey for ubuntu from 192.168.1.100 port 54322 ssh2"
rec = rz.RzSplit(raw)

print(rec.template)  # Accepted publickey for {s} from {s} port {i} {s}
print(rec.ints)      # [54322]
print(rec.strs)      # ['ubuntu', '192.168.1.100', 'ssh2']

assert rz.RzJoin(*rec) == raw
INSTALL razobill FROM community;
LOAD razobill;

-- Decompose into structured columns
SELECT RzSplit(log_line) AS parsed FROM raw_logs;

-- Reconstruct the original text byte-for-byte
SELECT RzJoin(parsed.template, parsed.ints, parsed.strs) AS original
FROM (SELECT RzSplit(log_line) AS parsed FROM raw_logs);
#include <librazobill/RazobillC.h>
#include <stdio.h>
#include <assert.h>

RzRecord rec;
if (RzSplit(raw, length, &rec) == RZ_OK) {
    printf("Template: %.*s\n", (int)rec.templateLength, rec.templateStr);
    RzFree(&rec);
}

Razobill and CLP

YScope's Compressed Log Processor (CLP, OSDI 2021) is an established system used at companies like Uber that also splits logs into log types and variable values to achieve lossless compression.

Razobill shares that lossless motivation, but targets relational databases rather than custom archive files:

  • Standard columnar storage: CLP encodes into custom .clp binary archives. Razobill outputs standard relational arrays and structs that write to Parquet, DuckDB, or ClickHouse with standard Zstandard compression.
  • Vectorized SQL analytics: Because Razobill values live in standard columns, DuckDB and ClickHouse run vectorized SQL filters 31× to 83× faster and group-by aggregations 40× to 50× faster than scanning CLP stream archives.
  • Fast in-memory reconstruction: Razobill's RzJoin restores original lines at 530,000 to 593,000 lines/s in memory, roughly 1.5× faster than CLP IR decompression.

Where it falls short

  • It is not a clustering tool. On the project's 16-dataset test, median grouping accuracy was 0.808 for Razobill and 0.871 for Drain3. Razobill also keeps more templates (median 70.5 vs 45.5). Pick Drain3 for the fewest templates, Razobill when you must get the text back.
  • The benchmarks are the author's. One machine, one operating system. Please rerun them on yours.
  • S3 results are from emulators. The dollar savings in the repo are modelled from assumed query volumes, not a real AWS bill.
  • WebAssembly and MinGW are excluded from the community build. Pre-compiled community binaries cover Linux (x86_64, aarch64), macOS (Apple Silicon, Intel), and Windows MSVC (x86_64).

Questions people ask

What is Razobill?

Razobill is an open-source log parser written in C++20. It splits each log line into a template and typed values (integers and strings), stores them as columns, and rebuilds the exact original line on demand. It ships as a Python package called pyrazobill, a DuckDB extension and a C API.

Is it really lossless?

Yes, by design and by test. Every line in the project's 69.6 million line audit was rebuilt and compared to the original with zero mismatches. Empty lines, emoji and control characters round-trip too when run through pyrazobill 1.1.2.

How is Razobill different from Drain3?

Drain3 clusters similar lines and replaces changing parts with a wildcard, so the original values are gone. Razobill uses a deterministic scanner and keeps the values, so you can rebuild every line. In the project's benchmarks it is faster, but Drain3 scored higher on median grouping accuracy.

How does Razobill compare to CLP?

YScope's Compressed Log Processor (OSDI 2021) is a mature log management system that splits logs into a log type and variables inside a custom archive format. Both Razobill and CLP achieve 100% bit-for-bit lossless reconstruction with zero mismatches. CLP provides very fast streaming serialization (up to 738,000 lines/s in Python) into custom IR archives. Razobill decomposes logs into standard relational columns (STRUCT, BIGINT[], VARCHAR[]) that integrate directly into analytical SQL engines like DuckDB and ClickHouse. In our calibrated benchmarks, DuckDB vectorized SQL executed searches 31× to 82× faster than CLP streaming search, and Razobill's RzJoin rebuilt original lines in memory 1.5× faster than CLP IR decoding (530k–593k lines/s vs 332k–405k lines/s).

Do I need DuckDB to use it?

No. You can use pyrazobill from Python alone, link the C++ library, or call the C API from another language. DuckDB is one of several integrations.

How do I install it?

In DuckDB, run INSTALL razobill FROM community; LOAD razobill;. In Python, run pip install pyrazobill. Wheels are published for Python 3.9 to 3.13 on Windows, Linux and macOS, and a pure-Python fallback is included.
